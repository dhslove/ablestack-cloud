## 목적 / Europa 방어 개선
정기백업과 VM 스냅샷의 공존 정합성 검증이 완료되지 않은 Europa에서는 **백업과 VM 스냅샷을 양방향으로 제한**하고 UI와 서버에서 같은 이유를 안내합니다.
장기 공존 지원은 #1149에서 별도 추진합니다. 이 이슈는 전체 비교 엔진이나 복원 후 백업 체인 전환 구현을 포함하지 않습니다.

## 코드 검토 결과 및 위험
소스 검토 기준: Europa 기반 53e1e0e0189b8955ddd2292832325671d2c36927. 구현 전 최신 upstream 재확인 필요.
- AblestackNasBackupProvider.assignVMToBackupOffering()/validateNoKvmFileBasedVmSnapshots()는 DiskAndMemory 스냅샷을 차단합니다.
- 같은 함수는 KVM 파일 기반 Disk 스냅샷을 발견하면 **snapshot coexistence testing 경고만 남기고 허용**합니다. Europa의 안전 정책과 일치하도록 이 예외를 제거해야 합니다.
- validateNasRestoreSnapshotCompatibility()는 기존 VM에 NAS 백업을 복원할 때 VM 스냅샷 존재를 이미 검사합니다. 공통 정책과 일치시키되 이 방어를 약화하지 않습니다.
- VM 스냅샷이 존재한다고 모든 백업이 반드시 손상된다는 뜻은 아닙니다. 그러나 외부 snapshot 체인 변경·복원·삭제와 백업 체크포인트 추적의 전체 수명주기가 검증되지 않았으므로, 이번 릴리즈는 보수적으로 상호 금지합니다.
- 단순 UI 숨김이나 NAS provider 한 경로 차단만으로는 API 직접 호출, 예약 실행, 동시 요청을 방어하지 못합니다.

## 범위와 정책
초기 필수 대상은 보고된 **KVM + ABLESTACK NAS/QCOW2 백업** 경로입니다. Europa VM UI의 공통 정책으로 노출하되 다른 backup provider/hypervisor는 지원 계약을 조사하여 적용 여부를 명시해야 합니다. 근거 없이 모든 외부 전문 백업 제공자를 동일 구현으로 간주하지 않습니다.

| 현재 상태 | 제한할 작업 | 유지할 기능 |
|---|---|---|
| 현재 VM에 삭제 완료되지 않은 백업 존재 | VM 스냅샷 생성, 기존 공존 스냅샷의 원본 VM 복원 | 목록/상세 조회, 안전한 정리 |
| 현재 VM에 백업 스케줄 존재(일시 중지 포함) | VM 스냅샷 생성·복원 | 스케줄 조회/중지/삭제 |
| VM 스냅샷 존재(디스크 전용·메모리 포함) | 수동/예약 백업 생성, 백업 스케줄 신규 설정 및 재활성화, 새 백업 오퍼링 할당 | 스냅샷/백업 조회, 안전한 정리 |
| 기존 백업과 VM 스냅샷이 이미 공존 | 새 백업·새 VM 스냅샷·원본 VM로의 양방향 복원 제한 | 양쪽 복구 지점 보존 및 조회 |
| 백업/스냅샷 작업 진행 또는 결과 미확정 | 반대 작업 및 충돌하는 복원/삭제 제한 | 상태 조회·재검사 |
| 자료는 없지만 추적 잔여물/조회 실패 | 생성·복원 가능하다고 단정하지 않고 상태 확인 필요로 차단 | 관리자 진단 |

- 존재 판정은 동일 VM의 모든 예약·수동 백업을 합산하며 현재 오퍼링만으로 좁히지 않습니다. 다른 오퍼링으로 바뀌었다고 과거 백업을 누락하면 안 됩니다.
- 실패/삭제 중 레코드는 보수적으로 검사합니다. 삭제 완료 tombstone은 제외하되 Error 상태만으로 잔여물이 없다고 판단하지 않습니다.
- 스케줄 중지만으로 허용하지 않습니다. 백업 오퍼링만 할당되고 백업/스케줄/추적 정보가 전혀 없는 경우는 이 조건만으로 신규 차단하지 않되, 기존 메모리 snapshot provider 제한은 유지합니다.
- 스냅샷/백업 삭제를 일괄 차단하여 정리 불능 상태를 만들지 않습니다. 기존 안전 검사와 실행 중 작업 검사를 유지하고 실패하면 복구 필요 상태를 표시합니다.
- 백업에서 **별도 새 VM 생성**은 원본 디스크를 되돌리는 작업과 구분합니다. 원본 충돌만으로 일괄 금지하지 않으며 기존 검증 유지.
- 볼륨 스냅샷은 VM 스냅샷과 별개입니다. 기존 볼륨 snapshot 방어를 약화하거나 이번 범위를 무조건 확장하지 않습니다.

## 서버 구현 계획
1. VM 단위 공통 충돌 검사 서비스(신규)를 만들고 machine-readable reason code 및 사용자 메시지를 반환합니다.
2. VMSnapshotManagerImpl 생성/복원 진입점, DefaultVMSnapshotStrategy 및 디스크 전용 전략 실행 직전에서 재검사합니다.
3. BackupManagerImpl의 createBackup/provider 호출 및 scheduleBackups() 예약 실행, 백업 스케줄 생성/갱신/재활성화 API, 오퍼링 할당에 적용합니다.
4. AblestackNasBackupProvider의 디스크 전용 공존 테스트 예외를 제거하고 모든 VM 스냅샷을 검사합니다.
5. 요청 접수 시 검사만 하지 않고 **동일 VM의 영속 작업 직렬화/잠금 아래에서 검사와 실행 권한 확보**를 수행합니다. 스냅샷 요청 두 단계 사이에 백업이 시작되는 TOCTOU 및 다중 관리 서버 경합 방어.
6. 기존 예약에 충돌이 있으면 백업 엔진을 실행하지 않고 명확한 차단 결과/이벤트를 기록합니다. 예약을 자동 삭제하거나 성공으로 기록하지 않으며 반복 실패 로그 폭증을 방지합니다.
7. 실제 checkpoint/bitmap 검사 비용은 매 UI 조회에 직접 호스트 조회하는 방식이 아니라 서버 관리 상태와 실행 전 agent 검증을 조합합니다. DB 빈 목록만으로 허용하지 않습니다.
8. 서버 capability/reason 응답을 UI가 사용하도록 기존 API 응답 확장을 검토합니다. UI에서 전체 backup 목록 조회 권한이 없어도 제한 여부는 알 수 있게 하되 권한 밖 복구 지점 정보를 노출하지 않습니다.

- engine/storage/snapshot/.../DefaultVMSnapshotStrategy.java 및 디스크 전용 snapshot 전략
- server/.../org/apache/cloudstack/backup/BackupManagerImpl.java

## UI 동작
- 탭 자체를 숨기지 않고 생성 버튼을 비활성화하며 상단 안내를 표시합니다. 탭 제목 영역은 추가하지 않습니다.
- VM 스냅샷 탭: “백업 또는 백업 스케줄이 있어 VM 스냅샷을 생성할 수 없습니다.” 디스크 전용·메모리 포함 모두 해당함을 명시합니다.
- 백업 탭: “VM 스냅샷이 있어 백업을 시작할 수 없습니다.” 백업 생성 및 새 스케줄 설정 버튼을 비활성화합니다.
- 안내에 제한 사유/권한 내 개수/관련 탭 이동을 제공하고, 단순 hover에만 의존하지 않습니다.
- 이미 열린 생성/스케줄 대화상자나 API 실행 직전 충돌은 서버 오류를 읽기 쉬운 차단 안내로 표시합니다. 백업/스냅샷을 자동 삭제하는 버튼을 넣지 않습니다.
- 기존 스케줄 편집은 중지/삭제 목적의 접근을 허용하되 충돌 중 새 실행을 활성화하는 저장은 차단합니다.
- 새로고침, 탭 전환, 생성/삭제 완료 후 서버 상태를 다시 조회합니다. 조회 실패 시 버튼을 활성화하지 않습니다.
- 대화상자 중앙 정렬, 제목/하단 버튼 고정, 내용만 스크롤. 다크모드의 안내·비활성 버튼·테이블·페이지 화살표 가독성 유지.
- 목업은 **제안 화면이며 실제 배포 결과가 아닙니다**. 백업 탭 이미지는 이미 백업과 스냅샷이 공존하는 기존 VM 예시입니다.

## 장기 과제와 관계
#1149는 안전한 공존과 변경 추적 정합성을 구현하는 장기 과제입니다. 이 이슈는 그 전까지 Europa에서 미검증 공존을 방지하는 별도 방어 작업입니다. 장기 지원이 완료되면 capability별로 제한을 완화하며, 이번 제한을 영구적인 플랫폼 제약으로 설명하지 않습니다.
