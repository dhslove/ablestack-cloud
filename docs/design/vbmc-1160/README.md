# #1160 가상 BMC 관리 UI 설계 보완

## 분석 기준

기존 Europa 소스 `9ee3e09ad1a`와 #1159 구현 PR #1164의 `f03bc2605a1718ef621cab1a6ca7a6494c98e5e9`를 함께 분석했다. #1164는 분석 시점에 OPEN이다. 이 목업은 해당 개선 코드 적용을 전제로 하며 병합 완료를 의미하지 않는다.

- `ui/src/config/section/compute.js`: 기존 할당/해제 작업과 password/allowedcidr 입력을 공통 관리 대화상자로 통합한다.
- `api/.../command/user/vm/{Allocate,Check,Remove}VbmcToVMCmd.java`: 기존 할당·검사·해제 API를 사용한다.
- `api/.../response/UserVmResponse.java`: vbmcport, vbmcstatus, vbmcaddress, vbmcallowedcidr, vbmclasterror를 사용한다.
- `server/.../vm/UserVmManagerImpl.java`: 할당 조건, 실제 검사, 원래 호스트 정리 확인, 실패 시 포트 유지, VM 수명주기 변경 제한을 UI에 반영한다.

## 진입 및 구성

별도 상시 탭을 추가하지 않는다. VM 작업 메뉴의 두 기존 작업을 **가상 BMC(IPMI) 관리**로 통합하며 상세 정보에서도 동일 대화상자로 연결한다. 할당 조건이 맞지 않더라도 조회 가능한 경우 관리 화면에서 사유를 설명한다. 이미 할당된 VM의 정리 경로는 새 할당 조건과 별도로 유지한다. API 권한에 따라 각 실행 버튼을 제어한다.

## API와 UI 상태 계약

| 화면 | 코드/API 근거 및 동작 |
|---|---|
| 미할당 | Unallocated. 실행 중 KVM, HA 비활성화, 정상/사용 호스트 조건 확인 후 할당 |
| 할당 설정 | allocateVbmcToVM: VM ID, password, allowedcidr. 계정은 vbmc 고정. 비밀번호는 공백/% 제외 ASCII 16~20자 |
| 접근 범위 | 기본은 127.0.0.1/32. 외부 허용 선택 시 단일 IPv4 CIDR 명시 입력. 이미지의 10.10.0.0/16은 예시이며 기본값이나 하드코딩 정책이 아님 |
| 마지막 확인 정상 | Ready는 저장된 검사 결과. 재진입 때 단순 포트 존재로 정상 판정하지 않고 상태 확인 권한/진행 상태에 따라 검사 수행 |
| 상태 확인 | checkVbmcToVM. Agent 인증/IPMI/도메인/방화벽 검사이며 사용자 PC에서의 외부 네트워크 도달성 보장은 아님 |
| 인증정보/CIDR 변경 | 전용 변경 API 없음. 명시적으로 해제 후 설정으로 이동하고 새 할당. 중단·포트 변경 가능성 고지. 해제 실패 시 다음 단계 금지 |
| 작업 중 | Allocating/Removing 및 조회 요청 중을 구분. 비동기 작업 결과 추적, 중복 제출 금지. 닫기는 작업 취소가 아님 |
| 정리 필요 | CleanupRequired. removeVbmcToVM으로 원래 호스트 정리 재시도. 정리 확인 전 포트 반환/새 할당 금지 |
| 결과 미확인 | 통신 실패 등 UI 요청 상태. 새 서버 enum을 가정하지 않음. 다시 조회하고 진행 작업 결과부터 확인 |
| 지원 불가/권한 없음 | 이유 표시 및 실행 금지. 서버 검증을 대체하지 않음 |

드롭다운은 `해제`, `인증정보·접근 범위 변경(해제 후 재할당)`을 제공한다. 비밀번호 조회/복사 기능은 제공하지 않는다. 명령 예시는 `-a`로 비밀번호 입력을 요청하고 실제 비밀을 포함하지 않는다.

## 기존 API에서 제공하지 않는 정보

- 서버 last_checked와 원래 할당 호스트 ID/이름은 현재 VM 응답에 없다. 목업의 확인 시각은 **이번 화면에서 검사 응답에 성공한 클라이언트 시각**이며 서버 기록처럼 표시하지 않는다. 재진입하면 이전 세션 확인 시각을 사용하지 않는다.
- 원래 할당 호스트를 현재 VM 호스트로 추정하지 않는다. 정확한 이력 표시를 추가하려면 읽기 응답에 필드를 추가해야 한다.
- 레거시 할당의 자동 정리 가능 여부/구조화된 사유 코드도 없다. 영문 오류 문자열을 파싱해 실행 가능 여부를 판단하지 않는다. 현재는 일반 관리자 안내와 서버 결과를 표시하며, 정밀한 자동/수동 분기는 읽기 계약 보완 후 구현한다.
- 기존 Ready 값만 받은 초기 화면은 `저장된 상태: 정상 / 현재 상태 확인 전`으로 표시한다. 검사 실패 시 정상 배지를 유지하지 않는다. 검사 권한이 없으면 마지막 서버 상태와 권한 안내만 표시한다.

## 화면 원칙 및 검토 범위

대화상자는 화면 중심 기준으로 배치하고 제목/하단 버튼은 고정, 본문만 스크롤한다. 일반 화면은 최대 폭 1000px, 좁은 화면은 좌우 24px 이상 여백과 화면 높이 제한을 적용한다. 고정 폭을 작은 화면에 강제하지 않는다. 긴 이름/주소는 줄바꿈 또는 툴팁, 접속 예시는 별도 줄바꿈을 제공한다.

다크 본문 #edf3f9, 보조문구 #c1cfdd, 배경 #252e37. 라이트 본문 #202b38, 보조문구 #46586b, 배경 #ffffff. 입력 필드·선·버튼은 테마 색을 따른다. 상태는 색뿐 아니라 텍스트로 구분한다.

목업은 정적 PNG 13장이다. 다크 9개 상태, 라이트 할당/정상/정리 필요 3장, 작은 화면 본문 스크롤 1장. 이는 설계 검토 자료이며 구현·실제 브라우저 검증·빌드·배포 완료를 의미하지 않는다. 구현 시 VM 스냅샷/호스트 장치의 공통 컴포넌트를 사용하고 실제 API 권한/비동기 결과/반응형 동작을 검증한다.


## 디자인 개정 (리뷰 반영)

평문 나열을 제거하고 조회 항목은 고정 레이블 열·구분선·줄바꿈을 가진 2열 정보 표로 통일했다. 할당 화면은 입력 필드/라디오 선택/필드별 도움말로 구분하며 입력 영역 시작점을 정렬했다. 상태 배너, 접속 명령 상자, 본문 및 고정 버튼 영역을 구분한다. 다크/라이트 13장 모두 교체했으며 긴 레이블 행 높이와 좁은 화면 배치를 조정했다.
